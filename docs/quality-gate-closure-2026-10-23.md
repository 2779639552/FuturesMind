# 研究内容检查的闭环（2026-10-23）

## 一、问题

`research_review` 在 2026-10-22 上线时只是**事后自检**：

```python
# web_app.py 旧代码
if not _rr.get("pass"):
    logger.warning("[research_review] %s", summarize(_rr))
```

三件事同时成立，等于没接上：

1. 警告只进日志，**不影响评级、不要求改写**
2. 前端 `web_template.html` 里搜 `research_review` **零命中** —— 界面上看不到
3. 检查发生在 `synthesis` **之后**，此时结论已经生成，检查结果无处可去

> 检查器报出的问题如果没人消费，它就不是检查节点，是自检日志。

## 二、改法：事前约束 + 事后验收

### 事前（图里的正式节点）

在 `debate_moderator → synthesis` 之间插入 `research_review` 节点：

```
技术/基本面/宏观/情绪 ─┐
                      ├→ 多方立论 → 空方反驳 → 多方再反驳 → 辩论裁决
                      │                                            ↓
                      └──────────────（无辩论时直连）─────→ research_review
                                                                   ↓
                                                              synthesis
```

- **纯规则，零 token、零延迟**（用 LLM 自查等于又生成一次，更不可靠）
- 检查对象：四份分析师报告 + 辩论纪要（16601 字，实测）
- 产物 `quality_gate` 写进 `AgentState`，由 `synthesis_node` 读走

注入位置在 `**Your Task**` **之前** —— 模型此刻还在决定"怎么判"，不是已经写完：

```
⚠️ 质量门：研究内容检查未通过（75 分）。给出评级之前必须先处理下列问题：
1. [HIGH] 基差率 8.56% 未注明分母 —— 基差率必须注明分母（现货/期货），两者不可混比
2. [HIGH] 给出了方向性判断，但全文没有失效/作废条件 —— ...
硬性要求：
① 每条要么在正文补齐，要么在「本次局限」段说明为何无法补，不许静默略过；
② HIGH 级一条都不许忽略；
③ 数据缺口写「未取到」，不许用「影响有限 / 整体中性」顶替。
```

**预算**：约束块实测 417 字（上限 700）。方法论块已超预算 2.3 倍，这块必须短，
所以只输出 high/medium、最多 4 条、每条带一句可执行动作。

### 事后（验收）

综合研判跑完后，对**最终文本**再跑一次同样的规则：

- 未通过 → `acceptance_section()` 生成一段 `## ⚠️ 质量门：未通过（XX 分）`
- 由 `apply_acceptance()` 追加到 `reports["synthesis"]` 末尾（返回新 dict，不原地改）
- 接口新增 `quality_gate: {pre_failed, post_failed, section}`

**为什么不改 RATING 头**：评级是模型的领域判断，按问题条数机械降档会制造
"看起来更保守、实际没有依据"的假象。检查器能确定的只有「这些点没交代清楚」，
所以它只补一段说明，把判断权交回给读报告的人。

## 四、验证

**单元/结构（27 条）**

- `gate_block`：通过返回空 / HIGH 排前 / low 级排除 / 最多 4 条 / ≤700 字 / 每条带动作
- `acceptance_section`：通过返回空 / 列出全部问题 / 声明不改评级 / 以 `##` 开头可直接拼接
- `apply_acceptance`：追加到末尾 / 不破坏 RATING 头 / 不原地改入参 / 无 synthesis 键也安全
- 节点：不合格产出约束 / 合格不产出 / 自身异常时 fail-open / 卡片取数失败不崩
- **★ 约束真的进提示词**：用捕获型 LLM 断言 `gate_block()` 的文本出现在送进模型的 prompt 里，
  且位置在 `**Your Task**` 之前；`quality_gate` 为空时提示词零改动
- 图结构：`research_review` 入边随辩论开关变化、出边只接 `synthesis`、极简档不注册

## 五、两个必须说清的边界

**① 未通过路径没有在真实运行里触发过。**
这次两处检查都是 100 分通过，所以"未通过 → 注入约束 → 模型照做"这条链，
只在单元测试里被证明到「约束块确实出现在 prompt 里」这一层，
**没有**证明"模型看到约束后真的改了结论"。后者需要构造一份不合格的输入跑真实分析。

**② R5（失效条件）存在假阴性。**
本次综合报告里没有**声明式**失效条件（没有"若 X 则本结论作废"），但 R5 没报，
因为正则命中了叙述句里的「双方**失效**价位均未触发」「不会根本**推翻**中性判断」。

```
_INVALIDATION = r"(失效|作废|被推翻|反向条件|止损|以下情况.{0,6}改变|推翻)"
```

这是「提到」与「声明」的差别，和 10-22 那次 R3 把「84% 分位」当成基差率值是同一类问题。
建议下一步收紧：失效词必须与条件标记（若/如果/一旦/跌破/突破/高于/低于）或价格数字出现在同句。

## 六、前端展示（14:10 补做）

`quality_gate` 进了接口但界面仍然看不见 —— 这一节把它补上。

**位置**：综合研判卡的标题栏，徽标三态：

| 状态 | 样式 | 文案 |
|---|---|---|
| 事后未通过 | 红（`badge-bear`） | `⚠ 质检未通过 · 72分` |
| 事前拦下、事后通过 | 琥珀（`badge-neutral`） | `✓ 质检通过 · 事前拦截 2 项` |
| 都通过 | 绿（`badge-bull`） | `✓ 质检通过` |

点徽标展开明细，分「事前（已作为硬约束注入提示词）」与「事后（仍未交代）」两组，
每条带 HIGH / MED / LOW 标签。默认收起，通过时连容器都不渲染。

**三个实现约束**

1. **复用既有徽标类**（`badge-bear/neutral/bull`），全部走 CSS 变量 ⇒ 暗色/浅色自动适配，不新造颜色
2. 明细文本过 `_esc()` —— 规则 detail 里会拼进品种名、读数标签，不能假设无 `<`
3. 点击 `stopPropagation` —— 否则冒泡到卡片，可能触发折叠

**验证**：浅色、暗色各截三态，人工看过；`tests/test_quality_gate_ui.py` **11 条**
（8 条静态 + 3 条 playwright 真渲染，断言徽标文案、默认收起、点击展开、事前/事后分组）。

> **踩到的坑**：模板用 `/static/marked.min.js` 绝对路径，`file://` 下 404 ⇒ 脚本在
> `const App = {` **之前**就抛 `marked is not defined`，整段不执行，`page.evaluate`
> 报的是 `App is not defined`（看起来像方法没定义，实际是依赖没加载）。
> 测试里改成相对路径并把两个依赖复制进 tmp 目录，同时在渲染前断言
> `typeof App === 'object'` —— 否则以后依赖一变，失败信息会误导到错误的方向。

## 七、R5 收紧：从「匹配词」到「逐句声明」（14:15 补做）

### 问题

旧实现：

```python
if _INVALIDATION.search(text):   # 全文任意位置命中"失效"就算有
    return []
```

于是一份**没写任何条件**的报告，只要出现一句「双方**失效**价位均未触发」就能通过。
和 10-22 那次把「84% 分位」当成基差率值是同一类错误：**只匹配词，不看语境**。

### 三版判据，前两版都被真实报告打回

| 版本 | 判据 | 实测后果 |
|---|---|---|
| v1 | 失效词 +（条件标记 或 数字）；或 触发标记 + 数字 | **7/14 误放行**：「价格低于 MA20（5,207）约 171 点」这种**描述现状**被判成条件 |
| v2 | 加上「条件标记」但保留「转为/改为」 | **2/14 仍误放行**：「现已被突破并**转为**支撑」「是短线多头**止损**」 |
| v3 | 必须出现**条件框架**（若/如果/一旦/除非/只要/则/失效条件…）且句中有失效词或触发标记 | **6 份误报消除，0 份新收紧** |

v3 的退化写法：失效词 + 数字（`止损位 6,100`）不带框架也认。

**已知残留**（写进注释，不假装没有）：`日度减仓 6,390 手是短线多头止损` 这类
「失效词 + 数字」的描述句仍会被当成条件。要根治得做句法分析，收益不值。

### 附带发现：中性评级原本不受约束

`_DIRECTION_WORDS` 不含「中性」，所以**中性报告永远不要求写失效条件** —— 而今天两次评级都是中性。
现改为：

- 有方向（偏多/偏空/做多…）却无失效条件 → **high**
- 只有中性/观望 → **medium**（中性不是方向性建议，罚轻一档，否则告警会变噪音）

### 附带改动：事后验收只看综合研判

原来：

```python
_review_text = "\n\n".join(synthesis + technical_analyst + fundamental_analyst)
```

拼接的后果是**分析师报告给结论顶包**：实测 14 份里，综合研判单独看只有 1 份缺失效条件，
拼接后全部通过。读者只看最终结论，验收就必须按最终结论判。

### 影响量化（最近 14 份有综合研判节的报告）

| | 份数 |
|---|---|
| 旧规则误报、新规则放行 | **6** |
| 旧规则放行、新规则收紧 | 0 |
| 两版都报（真实缺失） | 2 |

### ★ 首次拿到「闭环真的生效」的实证（14:17 的 BU 分析）

前几轮真实运行都是 pass/pass，未通过路径没被触发过。这次跑到了「事前拦下、事后通过」：

| | 结果 |
|---|---|
| 事前（综合研判之前） | score=**75**，pass=False，`R3_caliber_unstated`：基差率 16.1% 未注明分母 |
| 事后（最终报告） | score=**100**，pass=True |
| 徽标 | 琥珀：`✓ 质检通过 · 事前拦截 1 项` |

**模型确实照做了** —— 报告正文里出现了它自己写的一句：

> 质量门修正：基差率 **16.1% 必须注明为现货分母**：956/5,925=16.14%；
> 若按期货分母为 956/4,969=19.24%

这是整条链（规则检出 → 约束注入 → 模型改写 → 事后复核通过）第一次在真实运行里走通。
