AgentSense 使用手册

期货投研多智能体平台 —— 按当前实况编写，不含计划中的功能。

编写日期 2026-10-23 · 依据代码：web_app.py commodity_demo.py web_template.html · 界面结构、阶段数、接口数量均核对自源码

给同事发的内网使用说明是另一份：lan-user-guide-2026-10-23.html（只有"怎么用"，没有维护细节）。本文件面向维护者。

0三分钟上手

一次完整分析大致是两件事：四位分析师各写一份报告，然后经过辩论与裁决收成一个评级。

4 位分析师并行（技术 / 基本面 / 宏观 / 情绪）
        ↓
多空辩论 3 轮（多方立论 → 空方反驳 → 多方再反驳）
        ↓
辩论裁决（主持人）
        ↓
研究内容检查（规则）── 发现问题就写成硬约束 ─→ 约束下面这一步
        ↓
综合研判（给出 RATING / CONFIDENCE / SCORE）
        ↓
三情景分析

最短路径

1. 双击 start_webapp.bat（会自己弹一个控制台窗口，别关）。
2. 浏览器打开 http://127.0.0.1:5000。
3. 进入「运行分析」→ 选品种 → 点「开始分析」。
4. 等约 5~6 分钟（全程 10 个阶段，进度条实时走）。
5. 看页面底部的 RATING 横幅，以及「综合研判」卡。

1启动与访问

1.1 启动

双击 D:\AgentSense\AgentSense\start_webapp.bat。脚本第一行会 cd /d "%~dp0" 锚定到自身目录，因此从任何位置启动都一样（早期版本写死过别的机器路径，已修）。

启动到真正能访问需要 15~25 秒（要跑调度器、孤儿进程清扫、聚合修复）。这段时间打开页面会连不上，属正常。

1.2 访问地址

场景地址前提
本机http://127.0.0.1:5000无
局域网其他设备http://<本机IP>:5000服务监听 0.0.0.0:5000，且防火墙放行 5000 端口
公网见桌面的 AgentSense公网地址.bat隧道进程在跑

局域网放行用桌面归档目录里的 AgentSense局域网放行.bat（需管理员权限，只放行 5000 端口）。

1.3 守护与停止

  • 守护：计划任务每 5 分钟检查一次 5000 端口，端口空了会自动拉起服务。所以「进程自己消失又出现」不是灵异事件。
  • 停止：关掉那个控制台窗口，或在任务管理器结束对应 python 进程。
  • 重启：powershell -File scripts\restart_server.ps1（停旧 + 分离启动）。

重启前看一眼

如果采集任务正在跑（研报、仓单、情绪），不要重启 —— 重启会触发孤儿子进程回收，可能导致重复消费 LLM。等采集结束再重启。

1.4 什么改动需要重启

改了什么要重启吗
web_template.html（界面）不用。Flask 每次渲染都重读文件，刷新页面即可
web_app.py / 任何 .py要。新路由不重启会 404
.env要

快捷键页面主要用途
Ctrl+1运行分析跑一次完整多智能体分析，看评级与全部报告
Ctrl+2研报研报问答、每日总结、单品种汇总、观点总览

3运行分析

3.1 分析配置

控件说明
品种当前品种池 21 个（BR / BU / BZ / CF / CJ … ），下拉列出池内全部
日期分析基准日。默认今天
情绪分析师自动（有情绪数据才带）/ 始终包含 / 始终排除（仅 3 分析师）

3.2 分析深度（三档）

档位跑什么大致耗时
完整4 分析师 + 3 轮辩论 + 裁决 + 检查 + 综合研判 + 三情景约 5~6 分钟
轻量跳过辩论与情景，保留综合研判（仍有评级）省约 73%
极简只出四份基础报告最快，但没有评级

下面的三个勾选框（辩论对抗 / 综合研判 / 情景分析）与三档预设联动：取消「综合研判」会连锁关掉辩论与情景。也可单独微调。

极简档不产出评级

页面会明确提示「本档为极简运行」。如果后面看到没有 RATING 横幅，先确认是不是选了这一档。

3.3 十个阶段

进度条按顺序推进，每格对应图里的一个节点：

#阶段产出
1技术分析价格结构、均线、关键位、失效条件
2基本面基差、库存、利润、仓单
3宏观 / 新闻政策、宏观数据、跨品种传导
4情绪分析机构 vs 散户、情绪得分、分歧度
5多方立论多方第一轮
6空方反驳空方第一轮
7多方反驳多方最后发言（对等反驳权）
8辩论裁决共识点与分歧点
9综合研判最终评级
10情景分析乐观 / 中性 / 悲观三情景

第 8 与第 9 之间还会跑一个研究内容检查（纯规则、不到 1 秒，不占进度格），详见第 6 节。

3.4 结果怎么读

底部横幅是第一行机器可解析的评级头，格式固定：

RATING: 偏空 | CONFIDENCE: 中 | SCORE: 4
字段取值含义
RATING强烈看多 / 偏多 / 中性 / 偏空 / 强烈看空方向结论
CONFIDENCE高 / 中 / 低模型对自身结论的把握
SCORE0 ~ 100–4 偏空、5 中性、6–10 偏多

横幅右侧还会显示从报告里抽出的「预测幅度」，以及一张 预测 vs 实盘价格 卡（事后回看用）。

3.5 综合研判卡上的质检徽标

卡片标题右侧有三种颜色，点一下展开明细：

徽标含义要做什么
质检通过事前事后都没发现问题正常使用
质检通过 · 事前拦截 N 项研判之前发现 N 个问题，已作为硬约束要求模型处理，最终报告通过了点开看拦下了什么，多半能看出模型改了什么
质检未通过 · XX分最终报告仍有 HIGH 级问题（如基差率没写分母、没给失效条件）报告末尾会自动附一段问题清单，复核后再用结论

3.6 分析输入数据卡

展示本次喂给模型的原始读数（基差、库存、仓单、利润），每条带来源与时点。若某项取数失败，这里会显示为未取到，而不是 0 —— 这是刻意的，0 和「没数据」必须能区分。

4其他页面

4.1 技术面量化

两张主卡：技术指标（均线、RSI、MACD、布林带、关键位）与策略回测（选策略、周期、天数、是否允许重叠持仓）。另有跨品种对比与排序。

4.2 基本面量化（A1~A6）

卡内容
A1社会库存季节性 + 交易所仓单走势
A2库存周期四象限（库存 × 价格）
A3基差与期限结构
A4加工 / 进口利润口径
A5虚实盘比与逼仓识别
A6仓单明细：总览与排名、品种细则（仓库分布 / 品牌结构 / 仓库-厂库占比 / 当日增减）、历史走势

基差率有两个分母

同一份基差，除以现货价和除以期货价是两个数（例：7.89% 与 8.56%）。看到基差率一定要确认分母，两者不可直接比较，可按「现货价 ÷ 期货价」换算。系统在注入给模型的文本里会自动提示这一点。

4.3 情绪数据

得分与价格叠加、采集帖子、平台预测力、品种级方向准确率、情绪异动、多空分歧度、领先滞后、情绪排名、多维度对比、舆情事件提取。

右上「一键更新」会触发采集；采集覆盖多个平台，按帖子 ID 跨批次去重。

4.4 研报

四个二级页签：问答（对研报库提问，可选品种/类型）、每日总结（默认）、单品种（某品种的观点汇总）、观点总览（按品种横向对照）。

4.5 外文研报

上传外文 PDF 或图片，生成中文编译版 PDF。可配置是否保留原图、是否加洞察点评。

4.6 数据仓库（四块）

区块内容
① 卖方数据（卡名「查询控制」）按品种查卖方四源指标：总览、走势、明细
② 上传研报PDF / 图片 / Word 上传，自动抽文本、结构化、入库
③ 自传数据个人数据接口：上传自己的 CSV/Excel 作为数据源
④ 研报库已入库研报的检索与维护（含「一键修复」「采集最新研报」「本地导入」）

5数据从哪来

来源提供什么注意
国君四源基差、库存、仓单、加工利润基差单次查询 ≤180 天（模块自动分片）；库存/利润为全量接口，冷启动 6~18 秒
天勤（TQ）期货日线、实时行情短连接，每次重建约 5.4 秒；偶发 SSL 失败会回退新浪
AKShare（新浪等）日线兜底、宏观指数免费源，稳定性次于天勤
研报三源机构研报全文按到达日所在周归档（周一为周始）；入库幂等
微信读书通道公众号文章会话失效时会降级到封面模式并记录缺口
平台情绪采集抖音、小红书、微博等按帖子 ID 去重，重复率通常较高

三态纪律（很重要）

系统对「有没有数」分三种状态，绝不混为一谈：

  • rows > 0 —— 有数据
  • rows: 0 & available: true —— 确定没有（例如该品种本周确实零变动）
  • available: false —— 取数失败（接口挂了、超时、无权限）

所以看到「0」和看到「未取到」是两件事。模型也被要求：取数失败时必须写「未取到」，不许用「影响有限 / 整体中性」顶替。

6质量门怎么读

这是 2026-10-23 新增的一层：在给出评级前后各查一次报告内容，查的是"该交代的有没有交代"，不改评级。

6.1 两道关

什么时候查到问题怎么办
事前辩论裁决之后、综合研判之前把问题写成硬约束，插进综合研判的提示词（位置在任务说明之前），要求逐条处理
事后综合研判之后只查最终报告本身；仍不通过就把问题清单附在报告末尾

6.2 七条规则

码查什么级别
R1四源全挂却给了方向，且没说明缺口HIGH
R2可用读数漏提 ≥2 个（漏 1 个容忍）MED
R3写了「基差率 X%」却没注明分母HIGH
R4方向句附近既无数值也无指标词MED
R5给了立场却没写失效条件（什么情况下本结论作废）有方向 HIGH / 仅中性 MED
R6用了周频/滞后数据却没写数据时点MED
R7本品种产业链关键环节完全没提MED

只有 HIGH 会让「质检未通过」。分数 = 100 减去各条扣分（HIGH 25 / MED 12 / LOW 5）。

6.3 它不做什么

  • 不改评级。按问题条数机械降档，会制造「看起来更保守、实际没有依据」的假象。
  • 不判断观点对错。它只查"有没有交代清楚"，观点本身对不对要靠后面的实盘对照。
  • 不阻塞分析。检查器自己出异常时会放行，绝不会把整次分析拖垮。

8常见问题

页面打不开 / 显示 502

  1. 先看那个控制台窗口还在不在（关掉窗口 = 服务停了）。
  2. 刚启动的话等 25 秒 —— 服务要跑完初始化才开始监听。
  3. 用命令行验证时必须加 --noproxy '*'：本机走了代理会返回 502 或 000，看起来像服务挂了其实没有。 
    curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5000/

分析跑很久没动静

完整档正常 5~6 分钟。进度条若长时间停在某一格：

  • 看是不是卡在「综合研判」—— 它是最慢的单个节点，几十秒到一分多钟都属正常；
  • 页面有暂停 / 继续 / 停止三个按钮，可以先暂停再继续；
  • 真要中止就停止，然后换「轻量」档重跑。

盘中第一次分析特别慢

正常。日线磁盘缓存只在非交易时段生效（日盘 09:00–15:10、夜盘 21:00–23:30 一律不读不写），因为盘中最后一根 K 线还没定稿，落盘就是半根。盘中每次都要实拉天勤，约 5.4 秒；盘前/盘后/重启后的第一次分析才有缓存加速。

两个数对不上，哪个是对的

先别急着判定「数据源坏了」。同一指标在不同位置可能有三种差异，都不是 bug：

差异类型典型例子怎么确认
分母不同基差率 7.89%（现货分母）vs 8.56%（期货分母）看有没有注明分母
量纲不同0.0914（小数）vs 9.14（百分数）差 100 倍就是量纲
窗口不同SMA20 差几十点差在「截止到哪一天」

「数据仓库 → 卖方数据」和「分析输入数据卡」里的读数都带来源与时点，对照着看最快。

回看历史日期，结果像是最新的

这是已知限制，见第 9 节。技术面/基本面两个量化视图目前没有日期参数，永远取最新数据。分析历史日期时，报告里引用的价格可能不是那天的。

研报 / 公众号没有新内容

三个来源独立：邮件研报、合集通道、微信读书通道。任一通道失败通常不影响另外两个，历史经验是「通道断了但内容基本已从其他通道进来」。可在「数据仓库 → 研报库」按时间筛一下确认。

9已知边界（如实列出）

限制影响现状
量化视图没有日期参数回看历史日期时，技术/基本面数据仍是「最新」未修 需改缓存键与 5 个函数
盘中日线要实拉盘中首次分析多付约 5.4 秒未修 要天勤长连接复用
产业链数据仍是草稿21 品种 74 个环节，其中 50 个（68%）本系统没有数据源draft 只用于查漏，不参与判断
失效条件判据仍有边角「日度减仓 6,390 手是短线多头止损」这类描述句会被当成条件已知 已写进代码注释
没有意图识别入口固定为「品种 + 日期」，无法直接问「只看仓单异动」未做
没有结论跟踪不会自动检查「上一版写的失效条件是否已触发」未做
方法论块偏长技术块 1804 字、基本面块 2094 字（预算 800）待压 已靠"结论块前置"缓解

改动效果

同品种去重同品种+同交易日+同档位已在跑时返回 409 并交回 run_id，前端直接接管那次进度，不重跑也不报错
