前端整体美化与规划
不改变任何后端能力，只重做"看见的方式"

这是一份只规划、不动手的方案：先把 7 个页面的现状体检清楚，定义一套可被逐条验收的设计系统，再按"视觉 → 导航 → 组件"三期落地。所有改造都不动接口、不动元素 id、不新增依赖。

Section 0

结论摘要

当前的问题不是"不好看"，而是同一套页面里并存着三代设计语言：Apple 蓝的令牌层、各页残留的内联样式、以及为特定模块临时写的覆盖规则。再加上 7 个页面里有 2 个超过 5 屏，导航靠"模块说明点击展开"承担——于是视觉在漂移、结构在膨胀。

① 先收敛，再美化

模板里有 1508 处内联 style、357 个 hex 色值、59 处 !important。不先收敛，任何视觉规则都会被内联样式顶回去——这正是 10-14 那轮返工的原因。P0 只做这件事，收益最大、风险最低。

② 长页靠"二级页签"，不靠折叠

研报页 10492px、数据仓库 5568px、情绪页 4591px。折叠索引只是把长页变短，没有改变"一页塞 4 件事"。计划用页内二级页签把每页压到 ≤2.5 屏。

③ 投研终端的"美"= 对齐、密度、层次

不做装饰性渐变/阴影。目标是把 21 列的挤压表变成"分组列 + 首列冻结 + 密度切换"，把 45° 挤在一起的坐标轴变成自适应刻度——可读性就是美观。

一句话：P0 让全站看起来是"一套东西"（2 天）；P1 让每个页面只讲一件事（3~4 天）；P2 让表格与图表真正好用（3~5 天）。三期都可独立上线、独立回滚。

Section 2

五条设计原则

不是审美偏好，每一条都对应上面某个具体问题。

1 · 一屏一焦点

每页首屏只回答一个问题：「我现在该看什么」。答案是一个 KPI 条 + 一块主区域，其余内容进二级页签。对应问题 1、5。

2 · 数字优先

所有数值用等宽数字（tabular-nums）、右对齐、单位降一级字重与灰色。让"比较"发生在眼睛而不是鼠标。对应问题 2。

3 · 层次靠留白与分隔线

不用阴影、不用渐变、不用彩色底。层级由字号、字重、灰阶、间距四件事表达——这也是当前令牌层已经定下的方向，只是没被贯彻。对应问题 4。

4 · 密度可调，默认紧凑

投研场景一屏要有信息量。表格提供「舒适 / 紧凑」两档（行高 40 / 32），默认紧凑；不要用放大间距来"显得高级"。对应问题 2、5。

5 · 一处定义

颜色、字号、间距、圆角、表格、空态、加载态——每样只有一处定义。新增模块只能组合，不能新写一套。对应问题 8。

6 · 状态必须可辨

空 / 加载中 / 失败 / 确定无数据 四种状态用四种视觉，绝不复用同一句"加载中…"。这条与后端三态契约一一对应。对应问题 6。

3.5 暗色与响应式（同一套令牌，不做第二套皮肤）

暗色

同一套令牌，暗色只换值：面 #000/#1D1D1F、字 #F5F5F7、语义色提亮一档（#FF453A / #30D158）。不新增暗色专用规则；图表通过 CHART.* getter 自动跟随，切主题零重取数。

窄屏

≥1280 多列 / 768~1279 两列 / <768 单列。表格横向滚动 + 首列冻结；一级页签保持横滚，页内二级页签折叠为下拉。不追求手机端"完整投研"，但保证不溢出、不重叠。

可访问性底线

正文对比度 ≥4.5:1（灰字 #6E6E73 在白底 5.6:1）；方向不只用颜色区分，同时给文字（看多/看空/中性）；焦点态统一 3px 蓝色外环；所有图标按钮带 title。

Section 6

分期路线：三期，每期都能单独上线

排序原则：先做"改动小、收益全院共享"的事。P0 不碰结构，纯样式收敛；P1、P2 才动 DOM 与组件。

Phase P0约 2 天

视觉收敛：让全站看起来是同一套东西

  • 令牌补全：语义色分级（涨/跌/中性/信息/禁用）、圆角 3 档、阴影归零；新增的图表色登记进 CHART_COLOR_KEYS，保证切主题能重染。
  • 内联样式收敛：写脚本把 1508 处 style="…" 中可归类的（字号/颜色/间距/圆角）替换为类名，剩余按"确有动态值"白名单保留；目标降到 400 以内。
  • 组件样式统一：按钮三级、标签、卡片、表格、输入、空态四态、页头。
  • 表格基础：表头吸顶、数值右对齐 + tabular-nums、行高紧凑 32、斑马纹关闭。
  • 图表基础：图例上置、网格只留横向、主序列 2px、轴标签 12px 且禁止 45° 旋转（改自适应刻度）。

验收：双主题逐页截图；全量回归 0 新增红；表格/按钮/空态三个组件在 7 页外观一致；不新增任何元素 id 变更。

Phase P13~4 天

导航与结构：一页一事

  • 二级页签组件：在研报 / 数据仓库 / 技术面 / 基本面 / 情绪 / 外文六页接入；默认落在最有用的子页。
  • 页面头组件：标题 + 一句话说明 + 右侧操作区，替换现在"卡片标题即页面标题"的混用。
  • 全局品种上下文：右上角一个品种选择器，跨页保持（已有 _curVariety 机制，只是没露出）。
  • 降级方案：若某页结构风险高，先上"侧边吸顶目录"（纯 CSS + 滚动监听），不动卡片归属。

验收：_SEC_IDX_VER 同步 +1；div 配平护栏；每页 ≤2.5 屏；深链（hash）可回落；E2E 逐页点开子页签无 JS 错。

Phase P23~5 天

组件深化：表格与图表真正好用

  • 数据表组件：列分组切换、首列冻结、密度切换、行内展开/右侧抽屉、导出当前视图。
  • 图表升级：自适应时间刻度、事件标记点、多序列主次与悬停联动、图例折叠。
  • 详情抽屉：截面行点开看单品种详情，不跳页、不丢筛选条件。
  • 状态组件：骨架屏、失败重试、确定无数据三态统一（消灭常驻"加载中…"）。

验收：21 列不再同屏；情绪图无标签重叠；每个"加载中"都有对应的骨架或超时提示。

找东西变快

以前在研报页找「某品种历史观点」要滚 10 屏；之后点一次子页签就到。跨页看同一品种时，全局品种上下文让你不用每页重选。

表格能读了

21 列不再挤成 55px 一条；按"价格/库存/利润/结构"分组，首列冻结，数字右对齐，一眼能横向比较。

图表不再"糊"

状态不再含糊

空 / 在跑 / 失败 / 确实没有，四种状态四种样子。不会再出现"加载中…"挂一整天。

7.2 不承诺的部分

  • 不改信息口径：所有数字、单位、分位、三态语义原样保留；美化不允许"顺手改个数"。
  • 不改接口：P0~P2 不新增/不修改任何 /api/*（唯一例外是未来做"列组"时可能需要视图配置，届时单独评审）。
  • 不追求"看起来高级"：不加阴影、渐变、玻璃拟态；投研终端的高级感来自对齐与密度。
Section 8

风险与保障

"不影响前端"这条要求，落到工程上就是四件事：不动接口、不动 id、可回滚、每步可验收。

风险为什么会发生保障措施
改了 CSS 不生效1508 处内联 style 优先级高于类P0 先做收敛脚本；每改一个组件用浏览器 computedStyle 抽查，不靠肉眼
结构改动打翻折叠索引_secScan 按 DOM 扫描，卡片归属一变索引就错_SEC_IDX_VER +1；div 配平护栏；页面级 E2E 逐页展开/收起
切主题图表不换色新增色值没登记 CHART_COLOR_KEYS新色一律走 CHART.* getter；双主题截图对比
并发会话互相擦除同一份 web_template.html 被两个会话同时改改造期锁定单会话；每次改前备份到 backup/，改后核 md5
深链/书签失效子页签改变锚点语义保留 #tab-x 一级锚点；子页签用 #tab-x/sub 并做旧链接回落
长页拆分的空态某些子页在数据未就绪时是空的统一骨架屏 + "为什么空"的文案；禁止空白页

8.1 每期的"停车条件"

  • 全量回归必须与基线逐项一致（当前基线：47~48F / 6E，失败项为既有过期期望，不新增）；
  • 7 个页签在 1600 / 1280 / 390 三个宽度下无横向溢出、无元素重叠；
  • 亮/暗双主题截图人工过一遍，语义色不得出现在非语义位置；
  • 任何一期上线后可一键回滚到上一期备份（backup/web_template_<phase>_<ts>.html）。

下一步：这份方案先不动手。请你挑一个方向确认——① 只做 P0（2 天，风险最低，全站立刻统一）；② P0 + P1（一周内，长页问题一并解决）；③ 全做（含表格/图表组件）。确认后再按阶段落代码。
