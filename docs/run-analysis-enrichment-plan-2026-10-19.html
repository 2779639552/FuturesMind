进展 · P1 已实施（2026-10-19 17:45）

不做融合，改成「按数据轴分发」

原方案 P1 打算给技术/基本面各注入一个结论块、再让交易员做证据摘要。落地时改成了更彻底的一条： 不产生任何总分，把量化结论按数据轴直接拆给对应分析师，聚合留到最后一步（研究经理）。

接收方拿到什么明确不拿什么
技术分析师 价格轴：技术快照（均线/RSI/MACD/BOLL/ATR/持仓）+ 价格轴票（鹿希武、墨菲 ADXR·背离·突破、威科夫、周期阶段）+ 价格轴加权分 + 双线同破闸门状态 基差 / 库存 / 利润 —— 块内明写「勿据本块推翻产业逻辑，也勿据库存解释 K 线」
基本面分析师 基差 / 库存 / 利润三轴：三指标策略（库存×利润×基差 → 四类策略）+ 三轴票 + 各轴得分 + 虚实盘比 +「套利/对冲」这类结构性结论 价格轴 —— 块内明写「勿据此推断入场时点；若产业看多而盘面走弱，写『产业未获盘面确认』」
宏观/情绪都不给（它不参与这个分工）—
研究经理 两方结构化对照：各轴得分 + 每轴均值 + 一致性判定 + 闸门状态 + 裁决纪律 两边原文、任何总分 —— 它看到的是「技术 −1.00 偏空 / 基本面 +0.37 偏多 / 方向相反」

为什么按「轴」而不是按「书」分

每张票本来就带 axis，而轴对应的是数据来源：鹿希武、墨菲、威科夫读的都是 K 线，属同一根轴； 四象的估值腿读基差、驱动腿读库存，所以它在源头被拆成 axis_parts。 按书分会出现「墨菲 ADXR 该给谁」这种无解问题；按轴分不会。

裁决层只给流程，不给硬规则

研究经理拿到的是一段固定纪律，而不是一个提前算好的总分：

  • 同向 → 可给单边，置信度上调一档，但必须写失效条件
  • 反向 → 不得直接选边，输出「区间 + 触发条件 + 失效条件 + 时间止损」（18 组「谁赢」组合无一通过 Bonferroni，写死「某方优先」等于把掷硬币包装成方法）
  • 任一维缺失 → 写「该维度无数据」，不得用「中性」顶替
  • 频率纪律 → 库存是周频，不能支撑 ≤3 个交易日；技术面只在 ≤20 日窗口作确认器

落地时撞出来的三类问题（都已修）：
① 技术视图里泄漏了「库存」两个字——「库存周期」这张票的票名与说明都带库存，而它的方向其实由价格决定。 只改说明不够，票名也做了中性化（多空逻辑(周期阶段)），否则技术分析师照样会被引到产业数据上。
② 把「套利/对冲(适合反套)」误报成数据缺口——它不是方向票，两个分量已分别计入基差轴与库存轴。 判据要按方向票过滤，否则每遇到结构性结论就误报一次。
③ warm() 走 8s 超时就等于没预热——实测返回时缓存还是空的，首次分析照样拿不到块。预热线程必须阻塞到算完。

实现：tradingagents/dataflows/analyst_views.py（新增，三个视图 + 缓存/单飞/超时降级）。 接线：commodity_analysts.py 两个分析师节点 + research_manager.py；web_app.py 预热改为两条线。 护栏 tests/test_analyst_views.py 24 例，变异自检 8/8 全击杀。

01 · 现状

先看现在已经接了什么

分析链路是：4 个分析师（技术 / 基本面 / 宏观 / 情绪）→ 多空研究员辩论 → 研究经理 → 交易员 → 3 位风险辩论 → 组合经理。每个分析师都有工具白名单，并且已经有一套确定性注入（把关键读数直接拼进 system prompt，不依赖 LLM 是否调工具）。

数据是否进分析现在走哪条通道缺口
行情 / K线 / 技术指标已用 工具 get_futures_price / get_futures_indicators / get_verified_quote 只到"指标值"，没有"这套指标合起来是什么结论"
基差部分 工具 get_futures_basis（akshare → 100ppi 兜底） 没用国君基差（18/21 覆盖、含 SMM 口径与基差率）

基本面量化结论半用 方法论块算了四象与期限结构 没用 fund_module 的「三指标→四类策略」与「虚实盘比/逼仓」
研报 / 情绪 / 品种库已用 确定性注入 + 工具下钻 —

1.1 四个缺口

① 国君四源只在页面上

数据仓库页已经把「基差 / 仓单 / 期货库存 / 社会库存 / 加工利润」算成了带分位的指标，但分析链路一次都没读过它。

② 分析师拿到的是"原料"

工具返回 CSV，LLM 要自己从序列里推结论。同一份数据，页面上有明确结论（偏多/偏空、象限、策略类型），分析师却要重算一遍，且可能算错。

③ 没有横截面

单品种分析看不到它在 21 个品种里的相对位置——"这个品种的库存分位是 78%，但全池中位数是 55%"这种话现在说不出来。

④ 技能卡只喂了 31/65

用 _runtime_card_probe.py 实跑 RB：31 张卡真正出现在产物里。五书里组合层（Carver handcrafting）、执行层（Harris 滑点参数化）没有落点。

02 · 架构

数据层 → 结论层 → 双通道注入

沿用项目已验证的模式（analyst-context-injection）：关键读数确定性注入 system prompt，下钻才交给工具。新增的只是"数据"和"结论"两层。

L0 数据层 · 一次预取
gtja_overview（6h 缓存） quant_snapshot（5min） fund_verdict（10min） cross_section（全池 21） sentiment / research（已有）
↓ 统一装进 analysis_bundle(symbol, date)，与分析师并行预取；3s 超时降级为"只用已有缓存"
L1 结论层 · 压成结构化结论
技术：trend / resonance / key levels / ATR 基本面：三指标策略 / 象限 / 虚实盘比 库存：双口径背离标记 横截面：排名 + 分位
↓ 每块 ≤ 800 字，只放"会改变结论"的读数
L2 注入层 · 双通道
技术分析师（技术结论块） 基本面分析师（GTJA + 基本面结论块） 宏观（板块共振） 交易员（证据摘要 + 冲突规则）
@tool get_gtja_snapshot @tool get_quant_view @tool get_fund_view @tool get_cross_section

为什么不直接把 CSV 塞给 LLM：国君四源一个品种最多 16 个指标 + 175 天序列，原始数据几十 KB，既占 token 又需要模型自己做统计。而 quant_module / fund_module 已经把这些算成了 score / 象限 / 策略类型 —— 结论层只是把已有计算结果的"摘要"搬进提示，不新增一套计算。

2.1 为什么优先级是「一手库 > GTJA > 公开接口」

这不是"谁更准"的排名，而是三条判据合起来的结果：离原始口径多近、能不能追溯与复现、与站内其它页面是否同源。

判据一手品种库国君 GTJA公开接口（akshare / 100ppi）
口径硬度 用户导入的产业数据（厂内/社会库存、开工、产量、排产、裂差）。加工环节最少，很多指标公开源根本没有。 交易所注册仓单是准官方；基差优先取 SMM 现货指数；库存/利润是国君自建数据集。 聚合商二次加工，现货定义、地区、频率各家不一；兜底源（100ppi）与主源口径可能不同。
可追溯 块内带"最新值 + 日期 + 环比 + 近4期 + 分位"，可回指到具体模块。 接口原始字段（onWarrant / basisValue / dataType），单位不归一但一条序列一个定义。 命名别名、限流、字段变动都会让"同一个指标"悄悄换口径（FU/P/PG/PX 就踩过别名 KeyError）。
站内一致性 只在分析链路用，页面上没有对照。 数据仓库页、量化页基差/仓单都用它 —— 分析引用它，用户翻页核对时数字对得上。 与页面对不上时，用户会认为"分析在乱写"（哪怕只是口径差异）。

所以它是"有条件优先级"，不是无条件覆盖。只有当三个条件同时满足时才按这个顺序取值：
① 同一指标（都叫"社会库存"，不是"厂内库存" vs "社会库存"）；② 同一时段（同一天/同一周）；③ 同口径（同为日频、同为吨、同为现货指数）。
指标不同就不存在优先级问题 —— 一手库的"炼厂排产"和 GTJA 的"仓单"根本不是一回事。

四个降级条件（任何一条成立就往下让）

条件处理
高优先源是未来/计划值一手库的平衡表/排产表常把未来月份预填成计划值。只取 ≤ 今天的实际值；被排除的点数在句尾注明（"另有 3 个未来日期点，未计入"）。
该品种未导入一手库按品种导入，未导入就返回 NO_DATA 并落到 GTJA，不得编造，也不得把"没导入"当成"库存为 0"。
高优先源失败GTJA 的 available=false 是"取数失败"，不是"没数据"；此时降级到公开接口，并在块内写明"取自公开接口，GTJA 本次失败"。
高优先源过期一手库最新日期若落后 GTJA 超过一个发布周期（周频 >10 天 / 日频 >3 天），以 GTJA 为准并标注"一手库停在 X 月 X 日"。

落地时把优先级写成一个取值函数（pick(metric, as_of)），返回值带 source 字段；注入块里每条读数都署名来源。冲突要写出来，不要静默择一 —— 这和分析链路"三态不可混"是同一条纪律。

04 · 结论优化

"用结论优化结论"的核心：冲突消解

现在四个分析师各写各的，到了研究员/交易员阶段靠 LLM 自由发挥。加上结论块之后，必须给一张明确的裁决表，否则模型会把矛盾的两段都抄进结论。

技术面基本面处理输出
同向同向置信度上调一档；方向明确单边（可带仓位建议）
同向反向降级为区间/观望，必须写出两边证据与触发条件"分歧" + 触发/失效条件
中性同向按基本面方向，但标注"缺技术确认"轻仓/等待确认
反向反向同上（都是弱信号，不硬凑方向）观望
任一缺失—不得用缺失方的"中性"顶替，如实写"该维度无数据"—

这条规则同时接上 Carver 的"反自欺评估"（不给没把握的方向）与多空逻辑的"证据链"要求。

  • get_gtja_snapshot(symbol, window)：四源三态 + 分位 + 单位说明。

  • get_cross_section(metric, top_n)：21 品种排名（复用 quant ranking / fund matrix 的 10min 缓存）。

验收：工具调用成功率 ≥95%；单次分析的工具轮数 ≤ 现状 +1（防止模型到处乱查）；截面查询命中缓存 <50ms。

P3约 2 天

  • 按五书补落点：Carver 组合层（跨品种 handcrafting / forecast scaling）、Harris 执行层（按品种流动性的滑点参数）、鹿希武（交易计划落到交易员输出）、Murphy（多周期共振显式化）。
  • 每张新卡都要有"落在哪个节点/哪段注入/哪条规则"，写进映射表。

验收：探针输出 ≥45 张；新增的每张卡都能在"关掉对应注入/规则"时让某条测试变红。

06 · 成本

延迟与 token 预算

项现状（实测/代码约定）目标
GTJA 全量端点冷启动6~18s（6h 磁盘缓存）分析前预取；命中时 <50ms
GTJA 基差分片175 天/片 × 最多 6 片 ≈ 3.2s复用 overview 缓存，不在分析内现拉
quant 快照overview 5min / 基差 15min / 期限 60s 缓存直接读缓存
fund 全池矩阵10min 缓存，并发 6；冷启动 40s+禁止在分析里现算全池，只读缓存
注入 token现有三块方法论 ≈ 2.4k 字符新增 ≤1.2k tokens（三块合计）
单次分析总延迟—P95 增加 ≤12s

最容易翻车的一处：把 fund_module 的全池矩阵放进同步链路。它冷启动 40s 以上，而分析是用户点一次等一次的交互。正确做法是"读缓存 + 后台刷新"（stale-while-revalidate），缓存没有就退化为"本次不注入"，绝不能阻塞。

07 · 风险

风险与回滚

风险机制缓解
GTJA 限流/失败四源里有三源要打上游，分析时并发多只用缓存值；失败写"接口失败，未纳入"；不改用 0 顶替（三态纪律）
两个数据源打架方法论块（quant_methodology 现算）与 GTJA 同指标不同值权重声明：一手品种库 > GTJA > 公开接口；同口径以新日期为准，并在块内标注口径
提示词膨胀新块被塞在长提示中间，模型忽略全部放在 system prompt 最前；每块 ≤800 字；块首写"优先阅读"
结论被当事实模型把"量化信号"写成"事实"每个结论带 as_of 与来源；禁止反推；分歧必须写触发/失效条件
并发分析抢缓存同一品种多用户同时点分析单飞（single-flight）合并请求；缓存键含品种+日期

回滚方式：每一阶段都是"新增注入函数 + 新增工具 + 在节点里加几行"，删掉对应调用即恢复。不改现有工具的返回格式、不改数据库结构、不改页面接口。
