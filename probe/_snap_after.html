原版 TradingAgents 框架

TradingAgents 是 TauricResearch 开源的多智能体金融投研框架（65K+ Stars），原版面向美股市场。

原版架构

阶段节点说明
1. 分析师Market / Social / News / Fundamentals4位分析师串行运行，各自调用数据工具生成报告
2. 辩论Bull Researcher vs Bear Researcher基于分析师报告进行多轮对抗辩论，每方可引用数据反驳对方
3. 研究Research Manager审阅辩论记录，输出结构化投资计划（Buy/Overweight/Hold/Underweight/Sell）
4. 交易Trader基于研究计划制定具体交易（入场价/止损/仓位）
5. 风控Aggressive / Neutral / Conservative3位风控分析师进行三方辩论，评估风险
6. 决策Portfolio Manager综合研究+交易+风控，输出最终交易决策

原版局限性

  1. 串行分析师：4位分析师依次运行，4倍耗时，错误通过共享状态传播
  2. "传话游戏"效应：数据→分析师→辩论→研究→交易→风控→决策，5次LLM传递，精确数据退化为模糊文字
  3. 美股硬编码：4层代码深度绑定美股数据源（Alpha Vantage/Yahoo Finance/Reddit）
  4. 风控后置：风控在交易决策之后，方向已定无法修正
  5. 权重黑箱：LLM隐式判断权重，无可编程/可审计的权重机制

基本面量化 方法论: 《期货多空逻辑》— 库存 / 基差 / 利润 三指标系统 + 虚实盘比逼仓识别

① 三指标策略系统

库存(仓单分位) + 利润(加工/进口利润分位) + 基差(期货升贴水) → 单边或跨期。 三指标共振才有单边优势; 指标互相矛盾时转跨期(单边易被反复止损)。
加载中...

② 估值 + 驱动 二维四象

估值轴 = 基差率(越高 ⇒ 期货越便宜 ⇒ 估值越低 ⇒ 越偏多) · 驱动轴 = 库存分位反向(库存越低 ⇒ 驱动向上)。 这是品种分类工具, 不是择时工具 —— 入场时机仍需技术面。

③ 加工 / 进口利润口径

多装置口径分色并列、不合并 —— 合并会掩盖"同品种不同装置利润分化"这一关键信息。 低利润 = 亏损不可持续 → 偏多倾向; 高利润 = 刺激供给增量 → 偏空倾向。

④ 虚实盘比与逼仓识别

虚实盘比 = (主力合约持仓 ÷ 2) ÷ 仓单折手数。比值大 = 钱多货少 → 易涨(多逼空); 比值小 = 货多钱少 → 易跌(空逼多)。 书中明确无固定阈值, 需结合距交割远近; 本页 2.0 / 0.5 仅为把连续比值翻译成定性描述的经验档位。

数据来源：四家交易所官网每日「仓单日报」（郑商所 xlsx / 大商所接口 / 广期所接口 / 上期所日报表），每日 08:00 与 16:40 自动采集。
数据日期怎么算：日报只在交易日收盘后（约 16:00 起）发布，所以看板上的「数据日期」是最近一个已发布日报的交易日——上午/周末点「采集最新数据」看到前一个交易日是正常的，状态条会标明「已是最新」还是「待更新」。
仓单：已注册成标准仓单的货物数量，仓单增加=可供交割货源变多（偏空），减少=货源收紧（偏多）。
单位不统一：郑商所=张、大商所/广期所=手、上期所=吨（白银/黄金为千克、原油为桶），跨品种数量不可直接相加。
仓库 vs 厂库：厂库是生产企业自己的交割库（信用仓单），仓库是第三方仓储；两者结构变化反映交割货源的组织方式。
品牌维度：郑商所白糖/PTA 等、广期所多晶硅公布品牌；大商所与上期所日报不含品牌，对应模块会标注。
涨跌配色：红=仓单增加 / 绿=仓单减少。

本页做什么：汇总多渠道自动采集（发现报告 2 家 + 华泰天玑 21 品种日报 + 国泰君安云 API）与手工上传的研报， 经 LLM 结构化提取（品种 / 方向 / 基差·库存·开工率等指标 / 关键事件）与结论生成，形成 「研报问答」（页首）「研报每日总结」「单品种总结」（逐品种逻辑主线，未生成自动排队）「逐品种观点总览」四张视图；研报原件与逐篇明细在「数据仓库」页的研报库。
置信度（confidence）如何给出：不是公式计算，而是提取模型对「该方向判断」的把握度评分（0~1 小数）， 依据研报的方向倾向强度、数据与事件支撑是否充分、作者语气是否谨慎、证据间是否自洽，并按下列语义分档约束区间：
研报情形confidence 区间
明确看多/看空，且数据与事件支撑充分强0.75 ~ 0.95
方向倾向明确，但证据一般或语气谨慎0.55 ~ 0.75
中性 / 区间 / 无明确倾向0.4 ~ 0.6
几乎没给可判断方向的依据（方向宜判中性）；证据冲突取低档0.3 ~ 0.5
研报未给出置信度时显示「—(未给置信度)」，不拿 0.5 冒充；同一天的表内可横向比较， 数值是模型的判断把握度而非统计概率，仅供研究参考，非交易建议。

📖 模块说明 点击展开▶
国君数据(国泰君安期货 VIP cloudApi)：把平台上原本分散在各处的四个数据源汇成一页, 按品种一次性拿齐, 用于交叉验证研究结论 —— 基差看现货端赔率、仓单与库存看供给、 利润看产业可持续性。
四个源：① 基差/现货价(basisData) ② 交易所注册仓单(fut.warehouseStock) ③ 国君自建库存(inventoryData: 期货/社会/工厂三口径) ④ 加工/进口利润(processProfitData)。 后两者是全量数据集端点 —— 服务端忽略筛选参数, 需全量拉回本地筛, 故首次取数约 6~18 秒, 之后走 6 小时磁盘缓存。
三种状态必须分清(本页刻意分开显示, 请务必看颜色)： 有数据 / 确定无数据(接口正常应答 0 行, 如 SC 无现货指数口径, 基差必然为空) / 接口失败(本次取数出错 —— 此时"没数据"不代表该品种真的没有)。
口径声明：所有序列均为接口原始数值与原始单位, 平台不做单位归一(仓单各品种量纲不同)。 不同品种、不同源之间不可直接比大小, 只可在同一序列内做纵向比较。 分位为序列内占比(≤当前值的点数占比), 非区间线性插值。
已知覆盖缺口(实测)：基差在 SC/PX/FU/LU/CJ 为空; 利润在 SC/FU/LU/CJ/BU 无记录; 库存与仓单一周内覆盖近乎全池。用页面顶部的覆盖矩阵先确认再选品种, 可少走弯路。
